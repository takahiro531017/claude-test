# 仕入伝票チェックツール（試作版）

スキャンした仕入伝票（JPG / PNG / PDF）から AI（Claude のビジョン機能）で伝票番号を読み取り、
仕入一覧表（Excel）と自動で照合して、**人が確認すべきものだけ**を抜き出す Windows 向けデスクトップツールです。

> **データの取り扱い（重要）**
> - 伝票画像・仕入一覧表・読み取り結果は **このパソコンの中にだけ**保存されます（キャッシュ・手修正・確認済みの記録はローカルの SQLite、ログはローカルのログファイル）。
> - 外部へ送信されるのは、AI 読み取り時の **伝票画像の Anthropic API への送信のみ**です。仕入一覧表（Excel）の内容は送信しません。
> - 「テスト用（AIを使わない）」モードでは何も送信しません。
> - ログにはファイル名と件数程度しか書きません（伝票番号・金額・メーカー名は書きません）。
> - 画面の「ヘルプ → データの取り扱い・設定について」にも同じ内容があります。

## 設計の概要

**GUI は Tkinter** を採用しました（標準ライブラリで exe が小さく、PyInstaller 化が簡単。この用途の画面は Tkinter で十分。PySide6 は exe が100MB超になりがち）。

```
shiire-check/
  config.yaml               設定（モデル・リサイズ・正規化ルール・自信度のしきい値 ほか）
  run_app.py                起動用（PyInstaller のエントリ）
  build_exe.bat             exe 化
  shiire_check/
    config.py               設定の読込、APIキー取得、ログ設定
    normalize.py            伝票番号の正規化（全角半角・ハイフン・先頭ゼロ・スペース）、日付/金額/メーカー名の比較用処理
    schema.py               AI出力のスキーマ（pydantic）とツール定義
    imaging.py              フォルダ走査、PDFのページ分割、EXIF向き補正、長辺縮小
    reader.py               ClaudeReader（API）/ MockReader（テスト用）
    cache.py                SQLite：読み取りキャッシュ（画像ハッシュ）・手修正・確認済み/メモ
    pipeline.py             並列読み取り。1枚の失敗は隔離して続行
    matcher.py              照合ロジック（4区分＋警告）※GUI非依存
    excel_io.py             仕入一覧の読込、結果Excelの出力
    service.py              読み取り→照合→手修正→再照合の取りまとめ ※GUI非依存
    gui.py                  Tkinter 画面（処理は別スレッド）
  tools/make_dummy_data.py  ダミー伝票・ダミー仕入一覧表・モック定義の生成
  tests/                    単体テスト
```

データの流れ：

```
伝票フォルダ ─ページ展開(PDFは1ページずつ)→ ハッシュでキャッシュ確認 ─(未読のみ)→ 向き補正・縮小
   → Claude（report_slip ツールの強制呼び出し＝JSON）→ pydantic で検証 → SQLiteに保存
   → 照合（仕入一覧表と突き合わせ）→ 画面表示 → 手修正 → 再照合（AI再呼び出しなし）→ Excel出力
```

## インストール

Python 3.10 以上（Windows 版は python.org のインストーラ。Tkinter が同梱されます）。

```
cd shiire-check
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## APIキーの設定

Anthropic のコンソールで API キーを発行し、次のいずれかで設定します（**コードには書きません**）。

1. **環境変数（推奨）**：`setx ANTHROPIC_API_KEY "sk-ant-..."` を実行し、コマンドプロンプトを開き直す。
2. キーだけを書いたテキストファイルを作り、`config.yaml` の `api_key_file` にそのパスを書く。
3. `config.yaml` の `api_key` に直接書く（非推奨。ファイルを共有しないこと）。

## 毎日の使い方

1. 紙の伝票をスキャンして、1つのフォルダに保存（JPG / PNG / PDF。複数ページのPDFも可）。
2. 起動：`python -m shiire_check`（exe の場合は `ShiireCheck.exe` をダブルクリック）。
3. 「伝票フォルダ」と「仕入一覧表(Excel)」を選ぶ。**伝票番号の列**を選ぶ（見出し行から選択式。見出しに「伝票番号」等があれば自動で仮選択されます）。
   メーカー名・日付・金額の列は任意。指定すると、番号が一致した伝票について**金額・日付・メーカーの食い違いを警告**します。
4. 「照合開始」。進捗バーが進みます（画面は固まりません。「中止」も可能）。
5. 結果一覧を見る。色分け：緑＝一致 / 黄＝伝票なし / 赤＝一覧にない / 橙＝要確認 / ⚠＝警告つき。「表示」で絞り込み（「未確認のみ」が便利）。
6. 「要確認」の行を選ぶと、右に伝票画像とAIの読み取り内容が出ます。番号が違っていれば**「伝票番号の手修正」に入力して「修正して再照合」**（その場で再照合。修正はローカルに保存され、同じ伝票画像を次回読み込んだときにも反映）。確認し終えたら「確認済み」にチェック（一覧の「確認」列のクリックでも可）。担当者メモも書けます。
7. 「結果をExcelに出力」→ `仕入チェック結果_2026-10-05.xlsx` のように処理日つきで保存。シート「照合結果」「集計」。

### 区分の意味

| 区分 | 意味 |
|---|---|
| 一致 | 伝票番号が仕入一覧表に存在する（金額・日付・メーカーが食い違う場合は「一致（金額相違）」のように警告つき） |
| 伝票なし | 仕入一覧表にあるが、対応する伝票が見つからない |
| 一覧にない | 伝票はあるが、仕入一覧表に存在しない |
| 要確認 | 自信度が低い / 手書き / 番号が読み取れない / 候補が複数で特定できない / 読み取り失敗（通信障害・壊れたファイル等） |

**読み取れなかったもの・自信がないものは、絶対に「一致」にしません。** 同じ伝票番号が重複している場合（伝票同士・仕入一覧側）は「伝票番号重複」「一覧に重複」の警告が付きます。

## 試してみる（ダミーデータ・APIなし）

```
python tools/make_dummy_data.py          # sample_data/ に生成
python -m shiire_check
```

画面で「伝票フォルダ」= `sample_data/slips`、「仕入一覧表」= `sample_data/仕入一覧表.xlsx` を選び、
**「テスト用（AIを使わない）」にチェック**して「照合開始」。
ダミーには、形式の違う数社の伝票（A4縦・横長・レシート風）、斜め、全角表記、手書き風、複数ページPDF、EXIFで横向き保存されたJPEG、ぼやけ、
二重スキャン、API障害（模擬）、壊れたファイルが入っており、4区分すべてと警告が出ます。
モックは画像を読まず、`slips/_mock_readings.json` に書いた「AIの読み取り結果」を返します（実際のAI精度の確認にはなりません）。

## 設定（config.yaml）

使用モデル、画像の縮小上限（`image.max_long_edge`）、正規化ルール（`normalize`）、自信度のしきい値（`matching.min_confidence`）、
手書きの扱い、候補が複数のときの方針、金額/日付の許容差などを変えられます。各項目にコメントがあります。
設定ファイルは、環境変数 `SHIIRE_CONFIG` → 作業フォルダ → exe（またはプロジェクト）のフォルダ、の順に探します。

## exe 化（PyInstaller）

```
pip install -r requirements-dev.txt
build_exe.bat
```

`dist\ShiireCheck.exe` ができます。`config.yaml` を同じフォルダに置いて配布してください（APIキーは各PCの環境変数に設定）。
キャッシュとログは `%LOCALAPPDATA%\ShiireCheck\` に作られます。
※ このリポジトリの作業環境は Linux のため、**exe のビルドは Windows で未検証**です。起動時にモジュール不足のエラーが出たら、`build_exe.bat` の
`pyinstaller` に `--hidden-import <モジュール名>` を足してください。

## 判断したこと（妥当なデフォルトで進めた点）

- **GUI は Tkinter**（上記の理由）。
- **JSON の厳密な受け取り**：Claude に `report_slip` ツールの呼び出しを強制し（`tool_choice`）、返った引数を pydantic で検証。形式違反は「読み取り失敗」として「要確認」にする。
- **候補が複数のとき**：仕入一覧にある候補がちょうど1つなら「一致」（備考に注記）。それ以外（どれも無い／複数が一覧にある）は「要確認」。常に要確認にしたい場合は `matching.multi_candidate_policy: review`。
- **自信度が「中」**は一致扱い、「低」は要確認（しきい値は `min_confidence`）。**手書きは常に要確認**（`review_if_handwritten`）。
- **番号が読めている「要確認」の伝票**に対応する仕入一覧の行は「伝票なし」にしない（二重に出さない）。
  一方、**番号が全く読めなかった伝票**がある場合は、仕入一覧の未対応行は「伝票なし」に残し、備考に「読み取れなかった伝票がN枚あります」と出す。
- **正規化**は比較時のみで、元の表記は残す。先頭ゼロは「数字の連続の先頭」で除去（`004567`=`4567`、`TK-00123`=`TK-123`）。
  `10-0001` と `10-1` のようにハイフンの前後で桁を揃える表記は同一視しない（必要なら `remove_chars` から `-` を外す等で調整）。
- **手修正は伝票画像（ファイルのハッシュ＋ページ）に紐づけて保存**。同じ画像を再度読み込むと修正が復元される。AIの読み取り結果のキャッシュは「モデル＋プロンプト版」ごと。**失敗はキャッシュしない**。
- **画像の向き補正**は EXIF とPDFの向きまで。**斜め**の補正（傾き補正）は行わず、モデルの読み取りに任せる（試作の範囲。精度が足りなければ OpenCV での傾き補正を追加する）。
- **日付**列は Excel 出力の「日付」に、伝票から読み取った日付（なければ仕入一覧の日付、それもなければ処理日）を入れる。
- **見出し行**は既定1行目。シートと見出し行は画面で変更可能。**列は選択式**で、列名は固定しない。
- PDF は 200dpi で画像化し、1ページずつ読み取る。1ファイル最大200ページ（`image.max_pdf_pages`）。
- **Excel 出力**：`=` `+` `-` `@` で始まる値も数式にならないよう文字列で書き込む。
- 同じ内容の伝票を別ファイルで二重にスキャンした場合は「伝票番号重複」の警告（一致のまま）。

## 既知の制限（試作）

- 実際の API での読み取り精度は未検証（このリポジトリの作業環境から実APIは呼んでいません）。実伝票で数十枚試し、`min_confidence` やプロンプトを調整してください。
- Windows 実機での GUI 表示・exe 化は未検証（GUI は Linux 上の仮想ディスプレイで通しテスト済み）。
- 仕入一覧表は .xlsx のみ（.xls / .csv は未対応）。
- 「伝票なし」の行に後から伝票を割り当てる操作は未対応。
