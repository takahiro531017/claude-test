# 営業訪問管理アプリ

営業の訪問(いつ・誰が・どの店舗に行ったか)を記録し、店舗ごとの最終訪問日、月別の法人・店舗の件数、営業別の訪問件数を確認するアプリです。スマホ(ボトムナビ)とPC(サイドバー)の両方で使えます。

> ## ⚠️ 機密保持(必読)
> 担当店舗リスト(得意先・店舗・営業担当の対応)は **社外秘** です。
> - **社内ネットワーク内、または社内管理のサーバーでのみ運用してください。** インターネットに公開しない・社外のホスティングやクラウドに載せないこと。
> - このアプリは外部へ一切通信しません(外部API・解析・テレメトリ・CDN・外部フォント・クラウドDBなし。画面側もCSPで外部読み込みを禁止)。
> - マスタExcelと訪問DBは `.gitignore` 済みです。**`git add -f` で強制的に追加しないでください。**
> - テスト・サンプルは架空データのみ(`scripts/make_sample_master.py`)。実データをテストやドキュメントに書かないでください。
> - 未ログインではどのAPIもデータを返しません(401)。

## 技術構成と選定理由
| 項目 | 採用 | 理由 |
|---|---|---|
| サーバー | Python + FastAPI(1プロセス) | `pip install` と1コマンドで起動。Excel読み込みも容易 |
| DB | SQLite(`data/visits.db`) | サーバー不要、バックアップはファイルのコピー |
| フロント | ビルド不要のバニラJS/CSS + PWA | npm・CDN不要、全ファイルがローカル。グラフも自前SVG |
| 認証 | argon2ハッシュ + HttpOnly/SameSite=Strict のセッションCookie | パスワードを強いハッシュで保存 |
| 日付 | すべて日本時間(Asia/Tokyo)、月は暦月 | 要件どおり |

## 起動方法
Python 3.11 以上が必要です。

```bash
cd visit-manager
python3 -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 起動(同じPCだけで使う場合)
uvicorn app.main:app --host 127.0.0.1 --port 8000
# 社内LANの他の端末から使う場合
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

ブラウザで `http://<サーバーのアドレス>:8000/` を開きます。

初回起動時に管理者アカウント(ID: `admin`)が作られ、**一時パスワードがコンソールに1回だけ表示されます**。控えてログインし、パスワードを変更してください。

> **PWA(ホーム画面に追加)について**: ブラウザの仕様で、PWAのインストールとService Workerは `https://` または `localhost` でのみ動きます。社内LANで使う場合は、社内のリバースプロキシ等でHTTPS化し、`VM_SECURE_COOKIE=1` を設定してください。HTTPのままでも通常のWebアプリとしては問題なく使えます。

## Windowsで黒い画面なしに使う(`windows/` フォルダ)
`windows` フォルダの中のファイルを、`visit-manager` フォルダの直下(`app` と同じ場所)にコピーして使います。
| ファイル | 内容 |
|---|---|
| `start-app.vbs` | ダブルクリックで起動(黒い画面は出ません)。ブラウザも開きます |
| `stop-app.bat` | アプリを停止します |
| `auto-start-on.bat` | パソコンにログインしたとき、自動で起動するように設定します |
| `auto-start-off.bat` | 自動起動を解除します |

動作記録は `data/server.log` に追記されます(初回の管理者パスワードもここに残るので、ログイン後に消してください)。

## 初期セットアップ
1. 管理者でログイン → 「管理」→「担当店舗マスタの取り込み」で `担当店舗マスタ.xlsx` を選択して取り込む(または `python -m app.cli import-master data/担当店舗マスタ.xlsx`)。
2. 取り込みレポートを確認する(重複する得意先コード、店舗名の空欄、取り込めなかった行など)。
3. 営業ごとのユーザー(ID=営業コード)が自動作成され、**一時パスワードがその画面に1回だけ表示されます**。本人に安全な方法で伝えてください。初回ログイン時にパスワード変更が必須です。
4. 「管理」の「取引先名の候補一覧」で表記ゆれ(例: 「(株)○○」と「○○(株)」)を確認する。自動統合はしません。

## マスタの更新手順
1. 管理画面から新しいxlsxを取り込む(何度でも可)。得意先コードをキーに更新されます。
2. 既存の訪問履歴は消えず、得意先コードで紐づきます。
3. マスタから消えた店舗は削除せず「無効」にします(過去の訪問は残る)。
4. 担当営業が変わっても、**過去の訪問は訪問時点の営業で集計されたまま**です。

マスタの形式: 1シート目、列名は `営業コード / 営業担当者 / 得意先コード / 得意先名 / 店舗名`。得意先コードは文字列として扱います(数値で入っていて5桁未満なら0埋め)。同じ得意先コードが複数行ある場合は最初の行のみ採用し、残りはレポートに出します(勝手に削除はしません)。

## 集計の定義
- 訪問した店舗数・法人数は期間内の重複を除いた数。訪問回数は延べ件数。
  同じ店舗を同月に2回訪問 → 店舗数1、訪問回数2。
- 訪問率 = (担当店舗のうち期間内に訪問のあった店舗数) ÷ (担当店舗数)。営業を指定しない場合は有効な全店舗が分母。
- 最終訪問日は、誰が訪問したかに関わらず店舗単位の最新日。
- 月別・営業別・ホームはすべて同じ集計関数(`app/stats.py`)を使うため、画面間で数字は食い違いません。

## 権限
| | 営業 | 管理者 |
|---|---|---|
| 件数・最終訪問日の閲覧 | 全員分 | 全員分 |
| 訪問の登録・編集・削除 | 自分の分のみ | すべて |
| マスタ取り込み・ユーザー管理・設定・CSV出力 | 不可 | 可 |

## バックアップ
稼働中でも整合したコピーが取れます。
```bash
python -m app.cli backup backups/visits_$(date +%Y%m%d).db
```
バックアップ先も社内の管理された場所に置いてください(リポジトリには入れない)。復元はサーバーを止めて `data/visits.db` を差し替えます。定期実行は cron / タスクスケジューラで。

## 運用コマンド
```bash
python -m app.cli reset-password <ユーザーID>   # 一時パスワードの再発行(管理者パスワードを忘れた場合も)
python -m app.cli import-master data/担当店舗マスタ.xlsx
```
環境変数: `VM_DB_PATH`(DBファイルの場所、既定 `data/visits.db`)、`VM_SECURE_COOKIE=1`(HTTPS運用時)。

## 開発・テスト
```bash
pytest -q                                              # 集計・取り込み・権限の自動テスト(架空データ)
python scripts/make_sample_master.py data/sample.xlsx  # 架空マスタを作って動作確認
```

## 外部通信がないことの確認
- ブラウザの開発者ツール → Network で、リクエスト先がすべて自分のサーバー(同一オリジン)であること。
- サーバー側は外部へ接続するコードを持ちません(`requirements.txt` の各ライブラリも通信機能は使用していません)。

## 既知の制限
- オフライン入力は対象外(Service Workerは画面の枠のみキャッシュし、データはキャッシュしません)。
- ログイン失敗のロックはサーバー再起動で解除されます(プロセス内メモリ)。複数プロセスで動かす場合は共有されません。
