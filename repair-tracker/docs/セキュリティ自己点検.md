# セキュリティ自己点検(OWASP Top 10:2021 ベース)

実施者: 開発(Claude Code)による自己レビュー。**第三者診断(ペネトレーションテスト等)ではありません。** 本番公開前に、可能であれば外部の脆弱性診断を受けてください。
検証区分: **[自動]** = 自動テストで確認済み / **[設定]** = 設定・コードで実装したが実環境では未確認 / **[運用]** = 運用手順で担保

## OWASP Top 10 点検結果

| # | 項目 | 対策 | 区分 | 残リスク・対応 |
|---|---|---|---|---|
| A01 | アクセス制御の不備 | 全テーブルにRLS。4ロール×全操作の許可/拒否を84項目のDBテストで検証。他拠点の閲覧・登録・更新、viewerの書込、権限の自己昇格、物理削除、暗号文テーブルへの直接アクセス、写真(Storage)の他拠点アクセスがすべて拒否されることを確認。**MFA未通過(aal1)のJWTはDBが全拒否**。Edge Functionも毎回ロール・拠点・有効状態を確認し、拒否時は監査記録を残さない | [自動] | Realtime の DELETE イベントは行の中身でなく主キーのみ配信される仕様(個人情報は含まない)。実環境でRealtimeの配信範囲がRLSに従うことの確認が必要 |
| A02 | 暗号化の失敗 | 個人情報はAES-256-GCM(IV乱数、案件ID・項目名をAADに束縛、鍵番号つき)。鍵はDBと別管理。通信はHTTPS+HSTS。パスワードはSupabase Auth(bcrypt)。写真は非公開バケット+5分の署名付きURL。改ざん・差し替え・旧鍵での復号・鍵ローテーションをテスト | [自動] | 鍵は Edge Function のシークレットに存在するため、Supabase の組織管理者は理論上アクセス可能。管理者権限の最小化と二重管理(引継ぎ書)で対応。HTTPSの強制自体はホスティング側の設定(READMEの確認項目) |
| A03 | インジェクション | PostgREST/Supabase のパラメータ化クエリ。検索語は `, ( ) % * 引用符`等を除去してから `or()` に渡し、フィルタ構文を注入できないことをE2Eで確認。DBの `format()` はユーザー入力に使用していない。CSVは `= + - @` 始まりを無害化。XSSは React の自動エスケープのみ(`dangerouslySetInnerHTML`・`eval` 不使用をgrepで確認)+CSP | [自動] | — |
| A04 | 安全が確認されない設計 | 個人情報の最小化(任意入力・マスク既定)。**閲覧は監査記録が成功した場合のみ許可**(記録失敗時は平文を返さないことをテスト)。10分30回の閲覧回数制限。完了の取消はadminのみ。保持期間後の自動匿名化 | [自動] | 回数制限の値(30回/10分)は業務実態に合わせて調整が必要な可能性 |
| A05 | セキュリティの設定ミス | 自己登録無効、パスワード12文字、MFA有効、レート制限(`config.toml`)。CSP・HSTS・X-Frame-Options・nosniff・Referrer-Policy・Permissions-Policy(Vercel/Cloudflare/nginx用を用意)。CORSは `ALLOWED_ORIGIN` のみ。`.env` はGit除外、gitleaksをCIに設定。`service_role` キーはEdge Function内のみ | [設定] | **実環境で `config.toml` が反映されたか(特にSign ups無効、MFA、レート制限値)をダッシュボードで目視確認**すること。CSPの `*.supabase.co` は広め(独自ドメイン化したら絞る) |
| A06 | 脆弱で古いコンポーネント | `npm audit --omit=dev` を実施し、5件(high 3)を修正版へ更新して **0件**。CIで high 以上を失敗扱い。ロックファイル使用。Edge Function の外部インポートはバージョン固定 | [自動] | 継続的な更新は運用(四半期)。Dependabot の設定を追加済み |
| A07 | 識別と認証の失敗 | 招待制、12文字以上、TOTP必須(UI・DB・Edge Functionの3層)、ログイン失敗時の理由非開示、レート制限、無操作30分で自動ログアウト(単体テスト済み)、退職者の即時無効化 | [自動]/[設定] | 漏えい済みパスワードの照合(Supabase Pro以上の機能)は設定していない。パスワード再利用を教育で補う |
| A08 | ソフトウェアとデータの整合性 | 監査ログはハッシュ連鎖+更新/削除禁止トリガーで改ざん検知(トリガーを外して書換えても検出できることをテスト)。DB側で管理番号・拠点・作成者を不変化、`version`はサーバー採番。CIでテスト必須 | [自動] | GitHub Actions のアクションはタグ指定(コミットSHA固定ではない)。厳格にするならSHA固定を推奨 |
| A09 | ログと監視の不備 | ログイン/閲覧/作成/更新/ステータス変更/出力/権限変更を記録(値は記録しない)。管理画面で閲覧・絞り込み・改ざんチェック。月次で大量閲覧を確認する手順(運用マニュアル) | [自動]/[運用] | **異常の自動通知(アラート)は未実装**。月次の目視確認に依存。ログイン記録はクライアント送信(改造クライアントでは欠落し得る。Supabase Auth ログで補完) |
| A10 | SSRF | サーバー側でユーザー指定のURLを取得する処理は存在しない | — | — |

## 追加の点検項目

| 項目 | 結果 |
|---|---|
| 個人情報がログ・エラー・URL・ブラウザ保存領域に出ていないか | E2Eで localStorage/sessionStorage/コンソール/URL に平文がないことを確認 [自動]。Edge Function の `console.error` は固定文言のみ(例外内容を出さない)。ESLintで `console`・`localStorage` 使用を禁止 |
| 個人情報の一覧マスク | 一覧・ダッシュボード・カンバンはマスク値のみ取得 [自動:E2E] |
| 平文の表示は閲覧権限者のみ | hq_viewer/branch_viewer/他拠点は拒否 [自動] |
| CSV出力 | viewer不可、個人情報列は既定除外、admin明示時のみ、必ず監査 [自動] |
| ファイルアップロード | 種類・サイズ・マジックバイト検査(クライアント)、バケット側のMIME/サイズ制限、非公開 [自動:ロジック]/[設定:バケット] |
| ウイルス対策 | **未実装**。画像/PDFのみ許可で緩和。必要ならStorage Webhook+ClamAV を追加(セキュリティ設計書§9) |
| セッション | トークンは sessionStorage のみ。ブラウザを閉じると失効 |
| バックアップの暗号化・復元 | age暗号化→復元→件数・監査ログ連鎖の検証まで実機(PostgreSQL 16)で確認済み [自動/手動]。暗号文に平文が含まれないことも確認 |
| 権限昇格の経路 | `profiles` はadminのみ書込可。自己更新・自己INSERTが拒否されることをテスト [自動] |

## レビュー中に発見し、修正した問題(記録)

| 発見内容 | 対応 |
|---|---|
| 本番依存パッケージに脆弱性5件(high 3: ルーター、Supabase認証ライブラリ) | 修正版へ更新、`npm audit` 0件、E2E含む全テストで回帰なしを確認 |
| 個人情報の閲覧に回数制限がなく、乗っ取り・内部不正で大量持ち出しが可能 | 10分30回の制限を追加(429)。テスト済み |
| CSVの先頭BOMが受信側で失われ、Excelで文字化けする | BOMを付け直す処理を追加、Edge側のBOM出力もテスト |
| ステータス遷移関数の構文漏れ、トリガーが内部関数を呼べない権限不備 | DBテストで検出し修正 |
| 開発用ダミーユーザーにパスワードがなくログイン不能 | ログイン可能な形式に変更(開発専用であることを明記) |
| 認証イベントの重複でマスタ取得が3重に走る | 重複処理を抑止 |
| テストが検出した、写真テストデータの誤り(削除済み案件を参照) | テストデータを修正(権限不備ではない) |
