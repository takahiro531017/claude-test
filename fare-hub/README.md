# 運賃表ハブ（fare-hub）

各拠点（営業所・支社）発の運賃表PDFを取り込み、**1つのデータモデルに集約**して検索・比較・出力する社内向けローカルWebアプリ。

> 🔒 運賃表は**社外秘**です。このアプリは完全ローカルで動作し、外部通信を行いません。運用ルールは本書の「機密保持の運用ルール」を必ず確認してください。

## 「集約」の解釈

「全拠点の運賃表を `発地拠点 × 着地地帯 × サイズ → 運賃（税別円）` の1モデルに統合し、拠点間で比較できる」と解釈して実装しています（同一ルートの運賃を**足し合わせる**機能ではありません）。足し合わせが必要な場合は `app/service.py` の `combined_rows` を起点に拡張してください。

## 機能

| 機能 | 内容 |
|---|---|
| 取込 | 複数PDFをドラッグ&ドロップ。座標ベースでパースし、欠損・警告を表示。同一ファイル（SHA-256）は重複扱い、同一拠点・同一適用期日は再取込として置換 |
| 手動補正 | 「拠点別マトリクス」でセルをクリックして運賃を補正（黄枠）。ヘッダー（拠点名・期日等）も編集可 |
| 集約 | 拠点ごとに「基準日に有効な運賃表」を1つ選んで統合。期限切れ／期限間近(30日以内)／適用前を識別表示 |
| 検索・比較 | 発地・着地（**都道府県からも地帯を引ける**）・サイズを指定。最安拠点を緑でハイライト（期限切れ・適用前は比較対象外） |
| 一覧 | 拠点別マトリクス、全拠点の統合ビュー（サイズ別・地帯×拠点） |
| 注記 | 沖縄／離島／保険／出荷前提／サイズ・重量上限を分類して保持・参照 |
| 出力 | Excel（統合・比較・拠点別・注記シート）／CSV（UTF-8 BOM付き） |

## セットアップ

```bash
cd fare-hub
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt        # 初回のみネットワークが必要。以降の実行時は不要
python run.py                          # http://127.0.0.1:8765 （localhost固定）
```

動作確認用のダミーPDF（架空の拠点A〜C・乱数の運賃）を作る:

```bash
python -m tools.make_dummy_pdfs        # data/dummy/ に出力（Git管理外）
```

テストとセルフチェック:

```bash
python -m pytest                       # テスト中は外部ネットワーク接続を禁止している
python -m tools.selfcheck              # 外部通信なし／Git管理外／個人情報パターンなし
```

環境変数: `FARE_HUB_DB`（DBパス。既定 `data/fare_hub.sqlite`）、`FARE_HUB_PASSWORD`（設定するとBasic認証を要求）、`FARE_HUB_CONFIG_DIR`。

## データモデル（SQLite）

- `tariffs` … 1PDF＝1行（拠点、適用期日・満期日、見積No.、顧客コード、支払条件、締日、ファイルSHA-256）
- `rates` … `(tariff_id, region, size) → price`、`source` は `parsed`/`manual`
- `weights` … サイズごとの重量目安
- `notes` … 注記（分類付き）
- `warnings` … パース時の警告（種別と位置のみ。内容は含めない）

欠損セルは「12地帯×11サイズ − 登録済み」で都度計算するため、手動補正すると即座に解消されます。

## パーサー方針と調整方法

テキスト抽出の順序は信用せず、`pdfplumber` の単語座標から復元します。

1. サイズ見出し行（60〜260が6個以上並ぶ行）を探し、各サイズの**列のx座標**を得る
2. 地帯ラベル（正式名/別名の完全一致、最も左）から各**行のy座標**を得る
3. 数値セルを最も近い（行, 列）に割り当てる。許容差を超えるもの・重複したセルは採用せず警告
4. ヘッダー項目はラベル（`parser.yaml`）の右側の値を取得。1行に複数項目が並んでも分割
5. マトリクス下の行を注記として収集（`※`・`・`等で項目分割）しキーワードで分類
6. 取込後に**件数・欠損チェック**（12地帯×11サイズ＝132セル、重量目安、必須ヘッダー）

同梱の profile: `standard`（行=地帯・列=サイズ）、`branch_alt`（別ラベル・別名）、`transposed`（行=サイズ・列=地帯。地帯名・日付が字間をあけて配置される帳票向け。`word_x_tol` で文字をまとめる）。

拠点ごとにレイアウトが違う場合は、コードを変えずに `config/parser.yaml` に `profile` を追加します（全profileで解析し、最も完全な結果を採用）。地帯の表記ゆれは `regions.yaml` の `aliases`、都道府県の紐づけも同ファイルで変更できます。パースに失敗したときは「サイズ見出しが見つかりません」などの**種別のみ**が表示されます。

**実データでの検証手順（ローカルで実施）**
1. 取込後、画面の「欠損セル」「警告」の件数を確認
2. 元PDFと「拠点別マトリクス」を目視で突き合わせ（特に数行・数列）
3. ずれる場合は `parser.yaml` の `line_tol` / `row_tol` / ラベル候補を調整

## 機密保持の運用ルール

1. **外部通信なし**: フロントはCDN・外部フォント・解析ツールを使いません。CSPは `default-src 'self'`。FastAPIの `/docs` `/redoc` `/openapi.json`（外部CDNを読む）は無効化しています。サーバーは `127.0.0.1` にのみバインドし、Hostヘッダー検査（DNSリバインディング対策）とOrigin検査（他サイトからの書き込み対策）を行います。
2. **実データはコミットしない**: `data/`, `uploads/`, `exports/`, `*.pdf`, `*.sqlite`, `*.db`, `*.xlsx` は `.gitignore` 済み。取込んだPDF本体は保存しません（解析後に破棄。保存するのは抽出結果のみ）。DBは `data/` に作られます。
3. **ダミー値のみ**: テスト・サンプル・ドキュメント・コミットメッセージに実在の顧客名・住所・電話番号・運賃額を書かない。
4. **ログに中身を出さない**: ログはファイル名とエラー種別・件数のみ。uvicornのアクセスログ（URL）も無効。
5. **出力ファイルは社外秘**: Excel/CSVは社内ルールに従って保管・共有。CSV/Excelの数式インジェクション（`=`で始まる文字列）は無害化済み。
6. **将来のパスワード保護**: `FARE_HUB_PASSWORD` を設定すると全リクエストにBasic認証を要求します（認証は `app/security.py` に集約）。ローカル以外に公開する場合は、別途TLS終端を用意してください（本アプリはlocalhost専用の想定）。
7. **共有PC**: DBファイル（`data/`）を含むフォルダの権限を適切に管理し、不要になったら削除してください。

## 既知の制限

- スキャン画像のPDF（テキスト層なし）は非対応（OCRしません）
- 1ページ内に1つのマトリクスを想定（複数ページに分かれている場合は結合）
- 発地の項目ラベルが無い帳票は、ファイル名から拠点名を補完します（取込後に画面で修正可）
- 「ラベルの下に値がある」形式の項目（例: 顧客コード）は未対応です（画面で手入力）
- 実データでの検証は、列数・欠損・サイズ増加に伴う単調性など構造面のみ（金額の正誤は目視で確認してください）
