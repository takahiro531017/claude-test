## 1. 技術スタック案と選定理由

| 項目 | 採用案 | 理由 |
|---|---|---|
| 言語/Web | **Python 3.12 + FastAPI + Jinja2(サーバー描画)** | 1プロセスで完結。画面はHTML+少量のJavaScript(候補表示・下書き保存のみ)。ビルド工程(Node等)が不要で保守が楽 |
| DB | **SQLite(1ファイル)** + SQLAlchemy 2 | バックアップ=ファイルコピー。WALモードで同時アクセスにも十分(同時利用者は数名〜十数名想定) |
| PDF生成 | **ReportLab** | mm単位で寸法・トンボ・面付けを正確に制御でき、A5/A4のサイズが機械的にテストできる。純Python(OS非依存) |
| 日本語フォント | **IPAexゴシック(ライセンス上同梱可)をPDFに埋め込み** | プリンタ/ビューア側のフォント有無に左右されない。OSごとの文字化け事故を防ぐ |
| QRコード | **segno**(純Python) | 依存が軽い。URLを埋め込み、スマホ標準カメラで読める |
| 画像縮小 | **Pillow** | アップロード写真を長辺1280px・JPEG品質80程度に縮小、EXIF回転補正 |
| サーバー直接印刷 | Windows: **SumatraPDF(同梱・CLI)** / Linux・macOS: **CUPS(`lp`/`lpstat`)** | 下記6章。PDFを「用紙サイズ・向き・倍率を指定して」静かに印刷でき、追加の常駐ソフト不要 |
| 起動/常駐 | Windows: 起動用`.bat`+タスクスケジューラ(またはNSSM) / Linux: systemd / macOS: launchd | 手順をREADMEに記載 |
| テスト | pytest | 採番・遷移・正規化・統合・集計・PDF寸法/面付け |

**避けたもの**:クラウド必須構成、Node/SPAビルド、Docker必須(あっても動くが前提にしない)。
**フロントのJS**:素のJavaScript(+必要なら極小ライブラリ)。ログイン不要の端末記憶(担当者・下書き)は `localStorage`。

## 3. データベース設計(SQLite)

共通: `id INTEGER PK`、`created_at`、`updated_at`(ISO文字列)。論理削除は `is_active`。

### マスタ(自動蓄積型)
- **products**(商品=品番単位):`part_no`(表示用原文)、`part_no_key`(正規化キー・UNIQUE)、`name`、`maker_id`(FK)、`note`、`is_active`、`is_reviewed`(未整理フラグ)、`use_count`、`last_used_at`
- **makers**:`name`、`name_key`(UNIQUE)、`note`、`is_active`、`is_reviewed`、`use_count`、`last_used_at`
- **customers**(返品元):`name`、`name_key`(UNIQUE)、`is_active`、`is_reviewed`、`use_count`、`last_used_at`
- **defect_types**(不良内容の選択肢):`name`、`name_key`(UNIQUE)、`sort_order`、`is_active`、`is_reviewed`
- **staff**:`name`、`name_key`(UNIQUE)、`is_active`
- **master_aliases**:`kind`(product/maker/customer/defect/staff)、`alias_key`(UNIQUE per kind)、`target_id`。**統合した側の表記を覚えておき、今後その表記が入力されても統合先に自動で解決する**
- **master_merge_log**:`kind`、`from_id`、`to_id`、`moved_rows`、`by_user`、`at`(統合の記録)

### 返品データ
- **returns**:`receipt_no`(UNIQUE、RT-YYYYMMDD-NNN)、`received_on`、`staff_id`、`customer_id`、`product_id`、`part_no_text`、`product_name_text`、`maker_id`、`serial_no`、`quantity`、`defect_type_id`、`defect_text`、`reason_note`、`status`(received/checking/decided/done)、`disposition`(NULL/recycle/discard/maker_return)、`print_status`(unprinted/printed)、`printed_at`、`print_count`、`status_changed_at`、`closed_at`
  - 受付時の入力値は `part_no_text` 等に**文字列でも保持**(マスタ統合・編集後も受付時点の記録が残る。表示はマスタ参照を優先)
- **return_photos**:`return_id`、`file_path`、`thumb_path`、`taken_at`
- **return_events**(状況変更・操作の履歴):`return_id`、`at`、`actor`、`action`(create/status/disposition/edit/print/…)、`from_value`、`to_value`、`note`
- **receipt_counters**:`date_key`(YYYYMMDD)、`last_seq`(採番。トランザクション内で+1し重複を防止)

### 処分別(returns と 1:0..1)
- **recycle_details**:`return_id`(UNIQUE)、`repair_note`、`repair_staff`、`repair_done_on`、`price`、`buyer`、`sold_on`、`channel`、`repair_failed`(直らず→廃棄へ変更した印)
- **discard_details**:`return_id`(UNIQUE)、`discarded_on`、`method`、`vendor`、`reason`、`approver`(任意)
- **maker_return_details**:`return_id`(UNIQUE)、`maker_id`、`maker_status`(返送待ち/返送済/回答待ち/回答済)、`shipped_on`、`tracking_no`、`answer_type`(交換/返金/修理/対応不可/その他)、`answered_on`、`amount`、`answer_qty`、`note`
  - メーカー確認事項(品番・不良内容・製造番号)は returns から**自動引用して表示**(二重入力なし)

### 印刷
- **printers**:`display_name`、`conn_type`(browser/server/virtual_pdf)、`system_name`(OS上のプリンタ名)、`location_note`、`is_default`、`is_active`、`paper_size`(A5/A4/…)、`orientation`、`margin_top/right/bottom/left_mm`、`scale_mode`(actual/fit)、`tray`、`default_layout`(a5_single/a4_2up)、`default_copies`、`offset_x_mm`、`offset_y_mm`
- **print_jobs**(履歴+印刷待ち兼用):`status`(queued/printing/done/error)、`printer_id`、`layout`、`copies`、`requested_by`、`requested_at`、`finished_at`、`item_count`、`error_message`、`pdf_path`
- **print_job_items**:`job_id`、`return_id`
- **settings**:`key`、`value`(滞留しきい値、ベースURL、印刷方式、自動印刷方針[自動/確認/しない]、管理者パスワードハッシュ 等)
- **audit_log**:操作履歴(設定変更・マスタ編集/統合・ログイン含む)

主なインデックス:`returns(status)`, `returns(received_on)`, `returns(product_id)`, `returns(maker_id)`, 各マスタの `*_key`。

## 4. マスタ自動蓄積の設計方針(空の状態から開始)

### 4-1 正規化(保存時に自動)
`normalize_key(text)`:
1. Unicode **NFKC**(全角英数・記号→半角、半角カナ→全角カナ)
2. 前後空白除去、連続空白を1つに、全角スペースも同様
3. 英字は**大文字小文字を無視**(`casefold`)
4. **品番のみ**さらに:ハイフン類(`-` `‐` `−` `ー`系)・スラッシュ・空白の差を吸収したキーも持つ(`AB-123` / `AB 123` / `ＡＢ－１２３` を同一視)
5. 表示用の原文は**最初に登録された表記(NFKC・trim済)**を採用。以後同じキーなら新規作成せず既存に紐づく

### 4-2 自動蓄積の流れ(受付保存時、1トランザクション)
`resolve_or_create(kind, text)`:
1. キー計算 → `master_aliases` を先に確認(統合済みなら統合先)
2. 既存キーに一致 → その行を使用、`use_count++`
3. なければ**新規作成**(`is_reviewed=0`=「未整理の候補」へ)
4. 品番(商品)は、品番に紐づく商品名・メーカーが空で今回入力があれば**補完**。**既存の商品名と異なる場合は上書きせず警告**(入力画面に「この品番は以前『○○』で登録されています。商品名が違います。このまま登録しますか?」→ 返品データには入力どおり保存し、マスタは変えず、「未整理の候補(商品名相違)」に載せる)

### 4-3 候補表示
- 入力欄(返品元/品番/メーカー/不良内容/担当者)は `GET /api/suggest?kind=…&q=…` で**前方一致+部分一致、正規化キーで検索**(全角半角・大小を問わずヒット)、**使用回数の多い順/最近使った順**で上位8件
- 品番を選ぶ→商品名・メーカー名を自動入力(手で直すことも可)。新規品番はそのまま入力して保存可
- 通信できない場合も入力は続行でき、候補が出ないだけにする

### 4-4 重複・誤登録への対処(マスタ管理画面)
- **未整理の候補**タブ:①新規作成されたばかり(未確認) ②**類似の疑い**(正規化後の記号除去キーが同じ/編集距離1〜2/一方が他方を含む)③商品名相違の品番 を一覧。各行に「確認済みにする」「統合」「編集」
- **編集**:表示名の変更(キー再計算。他と衝突する場合は統合を案内)
- **削除/無効化**:使用実績ゼロ→物理削除可、実績あり→無効化(候補に出なくなる。過去データは残る)
- **統合**:移動元→移動先を選択→プレビュー(付け替え件数)→実行。1トランザクションで①returns等のFKを付け替え ②移動元キーを `master_aliases` に登録 ③移動元を無効化/削除 ④`master_merge_log`に記録。商品の統合時は、移動先に空欄の商品名/メーカーがあれば移動元から補完
- **CSV出力**(フェーズ3)/**CSV取込**(優先度低・最後に余裕があれば)

## 5. 受付票(A5)印刷レイアウト案

- 用紙:A5(148×210mm)。**縦(初期値案)**。理由:縦は現場で貼りやすく、受付番号・QR・項目を上から順に大きく並べやすい。横も設定で切替可(A4に2枚並べる場合は、**縦A5×2枚=A4横**に配置)
- 印刷専用レイアウト(画面とは別。PDFとブラウザ印刷用CSSの両方で同一デザイン)

│ 返品受付票                  2026/10/08 │
│ ┌──────────────────┐ ┌────────┐│
│ │ RT-20261008-001  (40pt太字) │ │  QR    ││  QR: 約35mm角
│ └──────────────────┘ │ (詳細URL)││
│ 返品元   ○○商事                  └────────┘│
│ ─────────────────────────────── │

│ メーカー ダミー電機                          │

- **A4に2枚(切り取りモード)**:A4縦(210×297mm)に、A5横(210×148.5mm)を上下2段、または A5縦を左右2枚(A4横)。**初期案=A4横に縦A5を左右2枚**(縦A5の貼り付け向きを保てる)。中央に切り取り線(破線+✂)、四隅にトンボ。1枚だけのとき片側は空白
- 長い文字列(商品名・不良内容)は自動で折り返し/フォント縮小(最小12pt)し、はみ出しを防止
- QRのURL:`{ベースURL}/r/{受付番号}`(詳細画面へ。要ログインでなく、担当者選択済みなら即操作可)

## 6. 印刷方式の仕組み・OS別の違い・推奨

### 方式1:ブラウザ印刷
`/print/{id}?layout=a5|a4_2up` に印刷専用HTMLを開く → `window.print()` → ブラウザのダイアログでプリンタを選ぶ。**どの端末でも動く**。ただしダイアログで毎回用紙サイズ/倍率を確認する必要があり、スマホからは実質使いにくい(スマホのプリンタ連携は機種依存)。

### 方式2:サーバー直接印刷
スマホで「印刷」→ サーバーが ReportLab でPDFを生成(A5実寸、トンボ付き面付け、オフセット反映)→ OSの印刷機能へ送信。

| OS | プリンタ検出 | 送信コマンド(用紙/向き/倍率/トレイ) | 備考 |
|---|---|---|---|
| **Windows** | PowerShell `Get-Printer`(印刷キュー一覧) | **SumatraPDF** `-print-to "名前" -print-settings "paper=A5,landscape,noscale\|fit,bin=…,copies=n" -silent`(同梱) | 一般的な社内PC構成。プリンタ側ドライバーで用紙設定が反映される。トレイ(`bin=`)はドライバー依存 |
| **Linux** | `lpstat -e`/`-p`(CUPS) | `lp -d 名前 -n 部数 -o media=A5 -o orientation-requested=3\|4 -o fit-to-page` | 最も安定。トレイは `-o InputSlot=`(`lpoptions -l`で取得可) |
| **macOS** | 同CUPS | 同上(`lp`) | 同上 |
| 仮想プリンタ | ― | `data/virtual_printer/` にPDFを保存(テスト用) | プリンタ無しで確認可。印刷履歴にも記録 |

- **「どれでも動く」設計**:OS判定して上表のアダプタを切替(`PrinterBackend` インターフェース+Windows/CUPS/Virtual実装)。手入力のプリンタ名指定も可
- **推奨**:**Windows 10/11 のPC 1台を常設**(ご担当者様が運用・保守しやすく、既存プリンタのドライバーもそのまま使えるため)。ただし印刷の安定性だけなら Linux/CUPS が最良。決まっていない場合は Windows を推奨
- 実行はバックグラウンドのジョブ(キュー)で行い、結果(成功/失敗/エラー文)を `print_jobs` に記録、失敗は画面から「再試行」
- 余白と位置ずれ:PDF生成時に `margin_*` と `offset_x/y_mm` を反映(プリンタ固有の非印字領域の補正)。テスト印刷=枠線・外形寸法(148×210mm)・目盛り(10mm刻み)・中心十字入りのページ

## 7. スマホ入力〜印刷の流れ(推奨)
1. スマホで受付登録(必須3項目で保存可)
2. 保存 → 設定の「登録後の動作」に従う
   - **自動で印刷** → サーバー直接印刷のジョブを投入(既定プリンタ)→ 完了トースト
   - **確認してから印刷** → 完了画面で「印刷する(プリンタ選択・部数・レイアウトを確認)」
   - **印刷しない** → 「印刷待ち」に溜め、PCの「まとめて印刷」でA4に2枚ずつ出力(切り取り運用)
3. 印刷された受付票を貼る → 以降は貼られたQRをスマホ標準カメラで読み取り → 詳細画面 → ステータス更新

## 8. HTTPSの扱い(比較と推奨)

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. HTTPのまま(推奨・初期)** | 写真=`<input type=file accept=image/* capture>`でカメラ起動/選択、QR=スマホ標準カメラ | 証明書不要。導入が最も簡単。要件(標準カメラで読める)を満たす | アプリ内QRスキャナ(カメラ直接起動)は使えない |
| B. 社内HTTPS(自己署名/社内CA) | Caddy等のリバースプロキシ+`mkcert`等で社内ルート証明書を作成し、各スマホに**証明書をインストールして信頼設定** | アプリ内QR読み取りが可能 | 端末ごとの証明書導入が必要(iPhoneは「プロファイル→証明書信頼設定」まで手順あり)。期限切れ運用が必要。ITに不慣れな現場には負担 |

**推奨はA。** 要件を満たし、保守が最小です。将来アプリ内スキャンが必要になった場合のみBを追加できるよう、手順書(READMEの付録)を用意します(フェーズ3)。

## 9. 固定IP・ホスト名での接続
QRに埋め込むURLが古くなると貼付済み受付票が読めなくなるため、重要です。
1. **ルーターのDHCP固定割り当て(IP予約)**でサーバーPCのIPを固定(推奨。PC側の固定IP設定より誤設定が少ない)
2. **ホスト名**:ルーター/社内DNSに`returns.local`等を登録できればそれをQRに使う。できない場合はmDNS(`PC名.local`。iPhoneは安定、Androidは機種により不可)
3. 設定画面の「**ベースURL**」を1か所で管理し、QRはそのURLから生成(IP変更時はここだけ変更。旧ラベル救済のため `/r/{受付番号}` の短い固定パスを使用)
4. READMEにWindowsファイアウォールの許可設定(ポート8000等)、起動の自動化手順を記載
